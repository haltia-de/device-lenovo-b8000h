# 0002. Версии, выпуски и пакеты

Дата: 18 октября 2026. Статус: принято.

## Контекст

После ADR 0001 оболочка, библиотека, настройки Firefox и программы живут в
своих репозиториях. Сборка образа клонирует каждый по тегу из
`linux-port/apps/sources` и собирает у себя — долго, требует сети и всего
окружения сборки (sysroot, Docker), а версии в репозиториях записаны
по-разному (`v1.0`, `v1.12.1`, `v3.0`).

## Решение

**Версии — SemVer, всегда три числа: `vX.Y.Z`.**

- X — несовместимое изменение того, на что опираются другие: команды и их
  аргументы, форматы файлов настроек и данных, ключи `X-B8K-…`, интерфейс
  библиотеки `b8k-compat`, протоколы между частями оболочки.
- Y — новые возможности без поломки старого.
- Z — исправления; изменение только упаковки — тоже новое Z.
- Тег `vX.Y.Z` = `pkgver` в `packaging/alpine/APKBUILD` = версия последнего
  `<release>` в AppStream metainfo = `__version__`/`pyproject.toml`, где они
  есть. `pkgrel` всегда 0.
- Старые теги с двумя числами (`v1.0`) остаются как есть; следующий выпуск
  каждого репозитория — уже с тремя.

**Выпуск — по пушу тега `vX.Y.Z`, в GitHub Actions.** Каждый репозиторий
вызывает общий workflow из репозитория `trudenboy/b8k-ci`. Он проверяет, что
версии в файлах совпадают с тегом, собирает пакет Alpine 3.24 (`abuild`)
— `noarch` на x86, `armv7` (оболочка, Видео с `b8k-vplay`) в эмуляции
Alpine armv7 — подписывает его и выкладывает в GitHub Release вместе с
`SHA256SUMS`.

**Подпись — ключом проекта.** Один ключ `abuild`: закрытый — секрет
`B8K_APK_PRIVKEY` в каждом репозитории (и копия у владельца вне репозиториев),
открытый — `linux-port/apk-keys/*.rsa.pub` здесь; сборка образа кладёт его в
`/etc/apk/keys`, и `apk` проверяет подпись сам.

**Образ ставит готовые пакеты по lock-файлу.**
`linux-port/apps/packages.lock` — строка на пакет: репозиторий, версия, имя
файла apk, его sha256. `build-rootfs.sh` скачивает пакеты из GitHub
Releases, сверяет sha256 и ставит `apk add` (зависимости — из Alpine).
`linux-port/apps/update-lock.sh` обновляет строки до последнего (или
указанного) выпуска. `linux-port/apps/sources` с тегами и сборкой из
исходников остаётся запасным путём (`B8K_FROM_SOURCE=1`) и для локальной
разработки (`B8K_APPS_SRC`).

## Последствия

- Сборка образа не собирает программы и оболочку и не требует их sysroot.
- Пакеты ставятся с префиксом `/usr` (программы, библиотека, Firefox);
  оболочка — по своим путям в `/usr/local` (их называют её сценарии).
  Программы ищут друг друга через `PATH`, а не по `/usr/local/bin`.
- Настройки, зависящие от системы (политики Firefox по пакету
  mobile-config-firefox), пишутся при установке пакета (`post-install`).
- Те же подписанные пакеты позже можно выложить хранилищем apk (GitHub
  Pages) без пересборки.
