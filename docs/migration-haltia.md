# План перехода на Haltia (ADR 0004)

**Состояние на 19 октября 2026, вечер:** фазы A, B и C пройдены, D почти
закрыта. Все репозитории в `haltia-de`, репозиторий пакетов работает,
все пакеты под именами `haltia-*`, вышли образы Pertin Haltia v2.0.0, v2.0.1,
v2.1.0, v2.2.0 и v2.2.1. Из фазы D осталось: merge request в pmaports, чтобы Haltia была
в списке оболочек `pmbootstrap`.

Составлен 19 октября 2026, когда организация `haltia-de` уже создана.
Шаг 1 ADR (точки подключения в оболочке) идёт отдельно, в сеансе оболочки.
Ниже шаги 2–4: организация, репозиторий пакетов, переименование. Каждая
фаза оставляет установленный планшет и сборку образа рабочими.

## Что сейчас ссылается на старые имена

- `uses: trudenboy/b8k-ci/.github/workflows/apk.yml@v1` в `release.yml` 11
  репозиториев, а внутри `apk.yml` ещё и `checkout` самого `trudenboy/b8k-ci`
  по тегу `v1`.
- Секрет `B8K_APK_PRIVKEY` в каждом репозитории.
- Публичный ключ `trudenboy-b8k-6ad4bb12.rsa.pub` (`linux-port/apk-keys/`).
  apk узнаёт ключ по имени файла, записанному в подписи пакета.
- `linux-port/apps/packages.lock` (столбец `trudenboy/b8k-*`),
  `linux-port/apps/sources` (адреса git), `linux-port/hybris/island.lock`
  (адрес выпуска), ссылки в README, `docs/`, `CLAUDE.md`.
- Описания репозиториев («для оболочки планшета lenovo-b8000h-linux»).
- Удалённые адреса локальных клонов `/mnt/data/Projects/b8k-*` и сеансы,
  которые в них работают.

## Фаза A. Организация, без переименований

Пакеты, команды и идентификаторы остаются прежними. Меняются только адреса
репозиториев.

1. **Настройки организации** (автор):
   - разрешить Actions;
   - `GITHUB_TOKEN` с правом записи для выпусков;
   - GitHub Pages;
   - секрет организации `B8K_APK_PRIVKEY` для всех репозиториев. Задать его
     можно на сайте или через `gh secret set --org haltia-de`, если у
     токена есть право `admin:org` (сейчас нет: `gh auth refresh -s admin:org`).
   - Репозиторий `haltia-de/.github` с README организации: история, знак,
     список программ.
2. **Перенос** (`gh api repos/trudenboy/<имя>/transfer -f new_owner=haltia-de
   -f new_name=<новое>`). GitHub перенаправляет старые адреса git, страниц и
   загрузок выпусков, поэтому `packages.lock` и `island.lock` продолжают
   работать и до правки. Порядок:
   1. `b8k-ci` → `ci`. Сразу поправить в `apk.yml` `checkout`
      `repository: haltia-de/ci` и передвинуть тег `v1`. Перенаправление для
      `uses:` переиспользуемых workflow не гарантировано, поэтому не
      полагаться на него.
   2. `b8k-compat` → `kit`, `b8k-shell` → `shell`, программы `b8k-<x>` →
      `<x>`, `b8k-firefox` → `firefox`. В каждом одним коммитом:
      `uses: haltia-de/ci/...@v1`, описание без «lenovo-b8000h-linux»,
      ссылки в README. Удалить секрет репозитория: теперь работает секрет
      организации.
   3. `lenovo-b8000h-linux` → `device-lenovo-b8000h`. Отношение форка к
      kz-creator сохраняется. Затем `packages.lock`, `sources`, `island.lock`,
      README, `docs/`, `CLAUDE.md` и `update-lock.sh` — на новые адреса.
3. **Проверка фазы:**
   - у каждого репозитория выпуск патч-версии, CI зелёный, apk подписан тем же
     ключом;
   - `update-lock.sh` в устройстве берёт его с нового адреса;
   - сборка образа (`image`, ручной запуск) проходит.
4. **Локальные клоны:** `git remote set-url`; сеансам репозиториев сообщить
   новые адреса.

Откат фазы: перенос обратно (`transfer` на `trudenboy`). Перенаправления
работают в обе стороны, пока старое имя не занято.

## Фаза B. Репозиторий пакетов

1. **`haltia-de/packages`**, workflow по событию выпуска в любом
   репозитории организации (`repository_dispatch` из `ci/apk.yml`) и по
   расписанию:
   - собирает apk последних выпусков;
   - строит и подписывает `APKINDEX` (`apk index`, `abuild-sign`);
   - публикует `https://haltia-de.github.io/packages/alpine/v3.24/<arch>/`.
   - Старые версии остаются в индексе: на них держатся закрепления и откат.
2. **Метапакеты** `haltia-desktop` и `haltia-desktop-ru` собираются там же
   (только зависимости, без файлов).
3. **Ключ:**
   - тот же закрытый ключ под новым именем `haltia-de-6ad4bb12.rsa.pub`;
   - пакет `haltia-keys` (подписан старым именем) ставит оба публичных ключа;
   - когда он на планшете, новое имя начинает подписывать индекс и пакеты.
   Новый ключ не нужен: меняется только имя.
4. **Устройство:**
   - `build-rootfs.sh` добавляет репозиторий и ключ и ставит пакеты по
     закреплённым версиям (`b8k-shell=1.6.0`);
   - `packages.lock` сохраняет вид, `update-lock.sh` и sha256: образ
     скачивает каждый закреплённый файл из репозитория (или из выпуска) и
     сверяет с lock, поэтому подменённый после записи lock файл ломает
     сборку, даже если индекс переподписан. Из репозитория берутся только
     зависимости, метапакеты и `haltia-keys`. Удержание по контрольной сумме
     (`имя><Q1…`) после установки убирается из `/etc/apk/world`, иначе оно
     держало бы `apk upgrade` на планшете;
   - `B8K_FROM_SOURCE=1` и `sources` остаются.
   - На планшете: `/etc/apk/repositories` с репозиторием Haltia, обновление
     через `apk upgrade`.

Откат фазы: `packages.lock` старого вида остаётся в истории, `build-rootfs.sh`
понимает оба вида до конца фазы C.

## Фаза C. Переименование одним окном

Каждый репозиторий выпускает новую мажорную версию. Порядок — от библиотеки
к образу. Перед публикацией всё ставится на живой планшет поверх нынешнего
набора.

1. **`haltia-kit`**:
   - модуль `haltia_kit`;
   - пакет `py3-haltia-kit` с `provides=py3-b8k-compat`, `replaces=py3-b8k-compat`;
   - модуль-переходник `b8k_compat`, который импортирует `haltia_kit` и
     предупреждает.
2. **`haltia-shell`**:
   - команды `haltia-*`, внутренние части в `/usr/libexec/haltia/`;
   - `/etc/haltia` с запасным чтением `/etc/b8k`, ссылка `/etc/b8k` →
     `/etc/haltia`;
   - `$XDG_RUNTIME_DIR/haltia/`, переменные `HALTIA_*`;
   - `apps.conf` знает старые и новые идентификаторы, перенос закреплений
     плиток;
   - `provides`/`replaces` пакета `b8k-shell`;
   - окна получают id `io.github.haltia_de.Shell` и `.TouchSettings`.
3. **Программы** (по таблице идентификаторов ADR 0004):
   - пакет `haltia-<x>` с `provides`/`replaces` пакета `b8k-<x>`;
   - новые `.desktop`, metainfo с `<replaces>`, иконки, имя D-Bus, `DesktopEntry`
     в MPRIS;
   - перенос настроек и данных со старого места при первом запуске;
   - старый `.desktop` с `NoDisplay=true` на одну-две версии;
   - слово «крупно» убирается из названий и описаний.
   Программы для российских сервисов идут в `haltia-desktop-ru`.
4. **`haltia-firefox`**: веб-программы в `apps.conf` и политики — по новым
   путям.
5. **Устройство:**
   - пакет `device-lenovo-b8000h`: службы `b8k-*`, `hooks/suspend`,
     `device.conf`, правила doas устройства;
   - в `build-rootfs.sh` метапакеты вместо списка;
   - устаревшие имена: `UI_PROFILE=shell`, `/var/log/session.log`, без
     `phoshdebug`, `gpu/tests/`;
   - образ **Pertin Haltia v2.0.0**, файлы
     `pertin-haltia-lenovo-b8000h-2.0.0-*`.
6. **Проверка окна на планшете:**
   - `apk upgrade` с нынешнего набора проходит без ручных шагов;
   - плитки и закрепления на месте;
   - счётчик MAX, отметка проигрывания, настройки программ и фильтра касаний
     сохранены;
   - в `/usr/local` ничего не осталось;
   - перезагрузка, сон, Wi-Fi работают.
   Затем чистая установка v2.0.0 с карты.

Откат фазы: старые пакеты лежат в индексе, поэтому достаточно
`apk add b8k-shell=<старая> …`. Новые пакеты не удаляют старые конфиги до
следующей мажорной версии.

## Правила фазы C (для каждого репозитория)

Проверено 19 октября 2026 в контейнере: пакет `haltia-x` с
`provides="b8k-x=$pkgver-r$pkgrel"` и `replaces="b8k-x"` сам заменяет
установленный `b8k-x` при `apk upgrade` (в `world` остаётся `b8k-x`, его
удовлетворяет `haltia-x` с большей версией). Изменённые человеком файлы в
`/etc` при этом остаются на месте.

| Репозиторий | Пакет: было → стало | Версия | Id: было → стало |
|---|---|---|---|
| kit | `py3-b8k-compat` → `py3-haltia-kit` (модуль `haltia_kit`, переходник `b8k_compat`) | 2.0.0 | — |
| shell | `b8k-shell` → `haltia-shell` | 2.0.0 | — → `io.github.haltia_de.Shell`, `b8k-touchguard-setup` → `io.github.haltia_de.TouchSettings` |
| max → messenger | `b8k-max` → `haltia-messenger` (команда `haltia-messenger`, название «Сообщения», репозиторий `haltia-de/messenger`) | 2.0.0 | `io.github.trudenboy.Max` → `io.github.haltia_de.Messenger` |
| paint | `b8k-paint` → `haltia-paint` | 4.0.0 | `…trudenboy.Paint` → `…haltia_de.Paint` |
| video | `b8k-video` → `haltia-video` | 2.0.0 | `…trudenboy.Video` → `…haltia_de.Video` |
| music | `b8k-music` → `haltia-music` | 2.0.0 | `…trudenboy.Music` → `…haltia_de.Music` |
| files | `b8k-files` → `haltia-files` | 2.0.0 | `…trudenboy.Files`, `.Gallery` → `…haltia_de.Files`, `.Gallery` |
| news, weather, calendar, text | `b8k-<x>` → `haltia-<x>` | 2.0.0 | `…trudenboy.<X>` → `…haltia_de.<X>` |
| firefox | `b8k-firefox` → `haltia-firefox` | 2.0.0 | — |

В каждом:

1. **APKBUILD:** `pkgname=haltia-<x>`, `provides="b8k-<x>=$pkgver-r$pkgrel"`,
   `replaces="b8k-<x>"` (у подпакетов `-pyc` так же); зависимости — по новым
   именам (`py3-haltia-kit`). В `pkgdesc` нет «крупно».
2. **Команды:** `haltia-<x>`; старое имя — ссылка на новое до следующей
   мажорной версии.
3. **Id** по таблице:
   - `.desktop` под новым именем с `X-Flatpak-RenamedFrom=<старый id>.desktop;`;
   - metainfo с новым `<id>` и `<replaces><id>старый</id></replaces>`;
   - иконка, id GApplication, `DesktopEntry` и имя MPRIS
     (`org.mpris.MediaPlayer2.io.github.haltia_de.<X>`);
   - старый `.desktop` с `NoDisplay=true` остаётся до следующей мажорной
     версии.
4. **Данные человека:** каталоги в `$XDG_CONFIG_HOME`, `$XDG_DATA_HOME`,
   `$XDG_CACHE_HOME` с именем `b8k-<x>` (или старым id) переносятся при
   первом запуске в `haltia-<x>`: `haltia_kit.migrate_dirs(old, new)`
   переименовывает каталог и оставляет на старом месте ссылку.
5. **Системные пути и переменные:**
   - `/etc/b8k/…` → `/etc/haltia/…`, `/usr/share/b8k` → `/usr/share/haltia`,
     `B8K_*` → `HALTIA_*`;
   - новое место читается первым, старое — запасным до следующей мажорной
     версии.
6. **Тексты:** слово «крупно» убирается из названий, описаний и README.
7. **Ключи `.desktop` оболочки:** `X-Haltia-Home`, `X-Haltia-Replaces`,
   `X-Haltia-Windows`. Оболочка 2.0 читает их первыми, а `X-B8K-*` — запасными
   до 3.0. Программы 2.0 пишут оба набора с одинаковыми значениями.
8. **Команды оболочки, которые вызывают снаружи** (`haltia-focus`,
   `haltia-launch` и другие, нужные программам, устройству и правилам doas),
   лежат в `/usr/bin` или `/usr/sbin`. В `/usr/libexec/haltia/` уходит только
   то, что вызывает сама оболочка.
9. **Выпуск** обычный (тег, `haltia-de/ci`). До выпуска apk ставится на
   планшет файлом поверх старого набора, и проверяются:
   - закрепления плиток;
   - счётчики;
   - MPRIS;
   - настройки после переноса.

**Порядок:**
1. `kit`: от него зависят программы.
2. `shell`: понимает старые и новые id.
3. Программы и `firefox` — в любом порядке.
4. Устройство: метапакеты `haltia-desktop` 2.0.0 по новым именам,
   `desktop.start` на `haltia-*`, пакет устройства, Pertin Haltia v2.0.0.
