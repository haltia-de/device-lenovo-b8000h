# Звонки и сон: на зарядке без глубокого сна

Задача #20, шаг 7 плана звонков (haltia-de/haltia, `docs/plans/calls.md`).
Решение автора: пока планшет на зарядке, он не засыпает — экран гаснет, а
Wi-Fi и Сообщения работают, звонок будит экран; на батарее — пробуждение по
сети, если MT6628 его умеет, иначе звонки только на активном планшете.

## Кто сейчас усыпляет планшет

`haltia-sleep` оболочки (haltia-de/shell, `libexec/haltia-sleep`): через
`SUSPEND_AFTER` = 30 с после того, как экран погашен (кнопкой или по
бездействию), если никто не держит ингибитор logind «sleep», он вызывает хук
устройства `/usr/lib/haltia/hooks/suspend`. У B8000-H это `b8k-suspend`: он
выгружает `wlan_mt6628` и `wmt` (драйвер сон не переживает), пишет `freeze` в
`/sys/power/state` (только s2idle) и после пробуждения загружает их снова.
Будит только кнопка Power. Во сне Wi-Fi выключен — Сообщения не получают
ничего, пока планшет не разбудят.

## Разделение

- **Оболочка** (`haltia-sleep`): правило «на внешнем питании не засыпать».
  Экран гаснет как раньше, системный сон пропускается; если зарядку вынули
  при тёмном экране — сон через `SUSPEND_AFTER` с этого момента.
- **Устройство** (этот репозиторий): надёжный признак внешнего питания,
  ответ про пробуждение по сети, замер потребления, приёмочная проверка на
  планшете.

Признак внешнего питания — `power_supply` типа USB или Mains с `online=1`:
на B8000-H это `/sys/class/power_supply/bq24190-charger` (bq24196, тип USB).
Статус батареи для этого хуже: с полной батареей на зарядке он `Full`, но
зарядник может показывать и «Not charging», продолжая питать систему.

## Пробуждение по сети (wake-on-WLAN) у MT6628

В нашем драйвере его нет:

- `wlan_mt6628` (драйвер MediaTek 2013 года, `linux-port/drivers/mt6628/wlan`)
  собран с `CFG_ENABLE_WAKEUP_ON_LAN 0` (`include/config.h`): код шаблонов
  пробуждения (`wlanoidSetAddWakeupPattern`, `CMD_ID_SET_RAW_PATTERN`) есть,
  но выключен. Более новой поддержки WoW (`CFG_SUPPORT_WOW` поздних версий) в
  этой версии нет.
- Драйвер не переживает s2idle, поэтому `b8k-suspend` выгружает его до сна:
  во сне чипа Wi-Fi для системы нет, ассоциация с точкой доступа рвётся.
- Чтобы будить по сети, нужно: научить драйвер приостанавливаться и
  возвращаться без выгрузки (SDIO с питанием во сне — у `&mmc3` уже стоит
  `keep-power-in-suspend`), сделать прерывание SDIO (DAT1, внутриполосное,
  отдельной линии EINT для Wi-Fi на этой плате нет: BGF EINT8 вешает SoC)
  источником пробуждения в `mtk-sd`, включить шаблоны в прошивке чипа и
  держать ассоциацию в режиме энергосбережения.
- Даже с этим разбудить планшет по сообщению MAX непросто: клиент держит
  TLS-соединение с сервером, «волшебного пакета» не будет; нужен шаблон на
  его TCP-поток или пробуждение на любой входящий пакет для нашего адреса.

Вывод: на батарее звонки только при активном планшете; пробуждение по сети —
отдельная большая задача (драйвер Wi-Fi, SDIO, прошивка), браться за неё
стоит после звонков на зарядке.

## Потребление на зарядке

Датчика тока у нас нет: драйвер батареи даёт только напряжение и процент
(кулонометр MT6320 не поднят), а на зарядке с полной батареей систему питает
адаптер. Замер — USB-тестером между адаптером и планшетом с погашенным
экраном и подключённым Wi-Fi. Отложен по решению автора (21 октября: сейчас
важнее работа звонков, тестера нет); результат будет здесь.
