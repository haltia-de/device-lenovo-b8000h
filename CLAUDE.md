# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An experimental port of Linux 7.1 + Alpine 3.24 armv7 to the Lenovo YOGA Tablet 10 **B8000-H** (MT8389/MT6589, 3G only, board `BLADE10_ROW_3GDATA`, stock firmware `B8000_A442_001_020_140620_WW_3GDATA`). Alpha quality. Until early October (kernel 22 era) the kernel crashed every 10–40 minutes with memory corruption; kernel 23 passed a one-hour full-load soak at 1.2 GHz with a 150 MB memory-pattern check and no errors. User-facing docs (`README.md`, `docs/*.md`) are written in **Russian**. Code comments and commit messages are in English: full-sentence subjects for fixes ("Pin the RDMA FIFO threshold that stops the Firefox scroll copies."), with `G5 step N:` / `kernel NN:` / `docs:` / `build-phoc:` prefixes for milestone work.

There is no test suite and no linter; CI only builds (see "Build pipeline"). A change is verified by building the images and running them on the tablet. The tablet gives you `dmesg` (often flooded by MSDC debug lines), `/sys/fs/pstore/*` after a crash or reboot, and `/var/log/session.log` (the session log; `phosh.log` on images before Pertin Haltia 2.0.1).

## Working on a connected tablet

- **SSH:** `user@<ip>` with a key (the development tablet: `192.168.10.208`); root commands go through `doas -n /usr/sbin/b8k-rootsh -c "sh -s"` with the script on stdin (without stdin it hangs). The tablet's IP comes from DHCP, so scan for an `OpenSSH_10.3` banner on the LAN to find it. Files go to it over HTTP from the PC (`/mnt/data/b8000h-build/work/keysrv`), not over scp (see "Wi-Fi hangs").
- **Updates on the tablet:** `doas haltia-update upgrade` (or Настройки → Обновления), not plain `apk upgrade`: it snapshots first, rolls back on failure and keeps `/etc/apk/world` clean. A rollback pins `name=version` in world on purpose until a newer version appears.
- **USB serial (development rootfs only):** `/dev/ttyACM0` on the host is a raw root shell (`acm-shell` on `ttyGS0`). It has no prompt or echo, so wrap each command between marker lines. The host user needs `dialout` group membership or an ACL. `make-release-rootfs.sh` removes this shell.
- **Running things in the session:** run them as `user` with the environment of the `waybar` process (`/proc/<pid>/environ`: `XDG_RUNTIME_DIR`, `WAYLAND_DISPLAY`, `DBUS_*`). `grim` takes screenshots. `haltia-launch start <app id>` opens programs (e.g. `io.github.haltia_de.Text`).
- **Power:** a failed `reboot` used to leave the tablet off; that is fixed by `b8k-wdt-exrst`. After `poweroff` with USB attached, LK shows the charging animation and stays off. Either way the user must press Power to bring it back, so ask before you power the tablet off.
- **Gotchas:**
  - The Python helpers run as `python3 /usr/bin/<name>` (or `/usr/libexec/haltia/<name>`), so `pkill -x <name>` and `killall <name>` miss them. Find the pid with `ps -o pid,args`.
  - `haltia-focus watch` reads `apps.conf` only at start. After you change it, restart the watcher, or a new program never shows its state and never asks to close.
  - Firefox reads `apps.conf` (for the web apps) only when it starts.
  - `pkill -f <pattern>` run over SSH also matches the remote shell that runs it, and kills your own command.
  - Killing `waybar` restarts the whole session and closes all programs. `kill -USR2 $(pidof waybar)` reloads its config and CSS in place.
  - Children of `haltia-launcher` that exit become zombies, because it `exec`s into waybar, which does not reap them. `pidof` still lists them.
  - The session loop of `/etc/local.d/desktop.start` keeps its text in memory from boot: an edit to the file takes effect only at the next boot (or after restarting the loop), and killing phoc restarts the session through the old text.
  - Only one `wvkbd` may run: a second input-method client makes phoc misbehave.
  - The USB ACM console does not come back after s2idle, and the host ACL on `/dev/ttyACM0` is lost when the device re-enumerates.

## Build pipeline

GitHub Actions builds everything (ADR 0003, `docs/adr/0003-ci-image.md`): workflow `image` on a `vX.Y.Z` tag runs `ci/kernel.sh` (`ci/sources.sh` fetches the kernel, the PowerVR DDK and openpvrsgx at pinned commits; `ci/apply-patches.sh` applies the series and makes the config; then kernel, modules, the GPU set kN, boot.img) and `ci/image.sh` (wpa_supplicant, `build-rootfs.sh` with the locked packages and the island of `linux-port/hybris/island.lock`, `make-release-rootfs.sh` on the fresh root) in the `ci/Dockerfile` environment, privileged, repo at /src, work at /opt/b8000h, and releases boot.img, the installer and root images (xz) and a kernel tarball; workflow `island` builds the Debian island (`ci/island.sh`, from public sources under qemu) as a release of its own. Steps reuse earlier work: `image` is jobs kernel (cached by the hash of its inputs, listed in the workflow), rootfs (from the kernel artifact: `build-rootfs.sh` takes `KERNEL_PKG`, the unpacked kernel tarball) and release; the island's base stage (`ISLAND_STAGE=base`: Debian, build deps, libhybris) is cached by the hash of `ci/island.sh` up to the line `log "build libhybris…"` (plus build-hybris.sh, tlspad.c, the Dockerfile), so files only phoc needs are copied after that line and a phoc patch rebuilds only phoc; the ci/Dockerfile image is cached by `.github/actions/build-env`. The same scripts run by hand in that container. `docs/INSTALL.md` §0 explains each step. The scripts hardcode work directories under `/opt/b8000h/` (`linux`, `rootfs`, `out`, `initramfs`, `release-root`). They were written for a WSL Alpine distro named `B8000Build` and run as root. Some scripts also copy output to `/mnt/c/Users/Public/MTK_B8000H/`. Build outputs go to `artifacts/linux-port/`, which is git-ignored, as are `backups/`, `build/` and `external/`.

1. **Kernel tree**: [TeamYogaBlade2/linux](https://github.com/TeamYogaBlade2/linux/tree/blade/v7.1) `blade/v7.1` @ `7dd245445adf`. Apply `linux-port/patches/` in numeric order. The patches come in three formats:
   - `*.patch`: apply with `git apply`.
   - `*.py`: idempotent string-replace scripts run against the kernel tree. They hardcode `K = '/opt/b8000h/linux-drm/...'`, assert that each anchor occurs exactly once, and print `already` when the change is present.
   - `*.txt`: whole DTS files or snapshots, e.g. `0011-b8000-h-install2-dts.txt` is the `install2` DTS. `*.patch.current.txt` holds the current state of an evolving patch.

   Config: `lenovo-blade_defconfig` (from the patches) with `CONFIG_LOCALVERSION="-b8000h25"` (patch 0038 enables zram; 0044 user namespaces and the USB role switch, kernel 24; 0045 netfilter with nftables and NFQUEUE as modules for `b8k-zapret`, kernel 25). The build number in the release selects the GPU module directory (`/usr/lib/b8k/kN`, parsed by `b8k-gpu` from `-b8000hN-`), so bump it whenever the kernel config changes, and install the new modules next to the old ones so that the previous `boot.img` still boots. The release must end in `-g<sha>-dirty`: in Docker, run `git config --global --add safe.directory <tree>` first, or `setlocalversion` drops the suffix. `CONFIG_ARM_APPENDED_DTB=y` is mandatory, because LK 0.5 passes only ATAGs.
2. **boot.img**:
   ```
   K=<kernel tree> DTB_VARIANT=install2 IMAGE_SUFFIX=-my sh linux-port/build-safe-image.sh
   ```
   The script builds `zImage + dtbs` with `ARCH=arm LLVM=1` and packs the initramfs from `linux-port/initramfs/init` plus the `splash.py` boot picture. It wraps the kernel and the ramdisk in 512-byte MTK headers (`tools/mkmtkimage.py`; the ramdisk label is `ROOTFS` for BOOT and `RECOVERY` for RECOVERY). It then runs `mkbootimg` with the stock header values: base `0x10000000`, pagesize 2048, board `39`. `tools/fix-legacy-boot-header.py` restores `second_addr=0x10f00000`, and a round-trip `unpack_bootimg` + `cmp` checks the result. `DTB_VARIANT` picks `mt6589-lenovo-b8000-h-<variant>.dtb`:
   - `safe`: no eMMC and no SD.
   - `sd`: rescue root on microSD.
   - `install`/`install2`: SD is `mmcblk0`, eMMC is `mmcblk1`.
   - `emmc`: root is USRDATA `/dev/mmcblk0p20`.
3. **External modules**: only the GPU set is built outside the tree: `pvrsrvkm` (DDK 1.12, sources fetched by `ci/sources.sh` into `external/mt6589-pvr-ddk-1.12` and `external/linux_openpvrsgx`), `dc_nohw`, `ion-legacy` (`build.sh` scripts in `linux-port/drivers/*`, run by `ci/kernel.sh`; the set goes to `/opt/b8000h/out/gpu-sets/kN` and into the kernel tarball as `usr/lib/b8k/kN`). `mt6628` Wi-Fi, the MT6589 sound driver and `b8k-battery` live in the same folders but patch 0033 builds them into the kernel (Wi-Fi as in-tree modules).
4. **wpa_supplicant**: `sh linux-port/wifi/build-wpa-nm.sh`. This build drops PMF/SAE/FILS/OWE support; without it NetworkManager cannot connect on the MT6628. See `docs/wifi-mt6628.md`.
5. **Root filesystem**: `UI_PROFILE=shell sh linux-port/build-rootfs.sh` (`phosh`, the old name, still works). The other profile, `labwc`, is the known-good rescue desktop. The script bootstraps Alpine through qemu-arm binfmt into `/opt/b8000h/rootfs`, installs the locked packages of the shell and the programs (see "Tablet shell"), the device helpers of `linux-port/rootfs/` and `linux-port/gpu/` (the `b8k-gpu` service), the kernel modules (`KERNEL_PKG`, an unpacked kernel tarball, or `KERNEL`, a built tree), the GPU sets (`GPU_SETS`) and the island (`ISLAND`).
   - The `shell` profile installs Haltia (see "Tablet shell" below), not Phosh. The audio stack (PulseAudio, ALSA tools, UCM) is listed explicitly. GNOME Settings and gnome-settings-daemon are gone since haltia-shell 2.3.0 (its own haltia-settings); iio-sensor-proxy (a service in default), feedbackd, desktop-file-utils (its trigger keeps `mimeinfo.cache`, without which GIO opens no links) and GTK's Russian translations come with the image, and the person's folders are Russian (`~/.config/user-dirs.dirs`: Загрузки, Документы, Изображения, Музыка, Видео; written in both `build-rootfs.sh` and `make-release-rootfs.sh`); no xdg-desktop-portal on the B8000-H (21 MB of RAM for nothing our programs use).
   - `00-b8k-modules.start` exists in two copies, in `build-rootfs.sh` and in `make-release-rootfs.sh`. Change both together.
   - `build-emmc-root-image.sh` packs that tree as a sparse ext4 image of at most 780 MB, because LK reports userdata as 800 MiB.
   - `linux-port/rootfs/make-release-rootfs.sh TAR BOOT OUTDIR [AUDIT]` takes a tar of a working tablet and builds the public image. It strips personal data and every Android binary, then fails if any audit pattern still occurs in the result.
   - `tools/mk-sd-installer.py root.ext4 boot.img out.img` builds the microSD installer image (`B8KINST1` format, consumed by `initramfs/init`).
6. **GPU stack**: an armhf Debian "island" chroot in `/opt/debian` (`linux-port/hybris/debian-enter.sh` enters it on the tablet), built by `ci/island.sh` (debootstrap under qemu; `build-hybris.sh` builds libhybris for the Android 4.4.2 / API 19 blobs, `build-phoc.sh` builds phoc 0.55.1 with `wlroots-0.20-hybris.patch` and `phoc-0.55.1-touch-cancel.patch`, which makes phoc honour libinput's touch cancel (a palm from `b8k-touchguard`); then trimmed to phoc's libraries) and pinned by URL and sha256 in `linux-port/hybris/island.lock`. Only phoc renders through GLES 2.0 on the SGX544. GTK4 needs ES 3.0, so apps stay on the CPU. Design notes: `docs/g4-hybris.md`.

## Tablet shell

The tablet runs **Haltia**, the calm touch desktop; the images of this repository are **Pertin Haltia** for the B8000-H. Everything about Haltia as a whole lives in the root repository **haltia-de/haltia** (local clone `/mnt/data/Projects/haltia-de/haltia`): the architecture, ADRs 0001, 0002, 0004 and 0005 (this repository keeps ADR 0003 and numbers its own new decisions from 0100), the plans, the registry of repositories (`docs/repos.md`), the shared conventions (`docs/conventions.md`: releases through haltia-de/ci, deb and Flatpak, NEWS.md and metainfo, signing keys, program ids, XDG paths) and the public keys. The agent started there is the architect and orchestrator (ADR 0005); this repository's agent is the executor for the kernel, the image and the version locks. The shell is haltia-de/shell (local clone `/mnt/data/Projects/b8k-shell`; its CLAUDE.md and `docs/shell.md` describe it in full); the programs and the library kit are repositories of the same organization (local clones `/mnt/data/Projects/b8k-*`). haltia-de/packages publishes the signed apk, apt and Flatpak repositories every 30 minutes, right after each release, or by hand (`gh workflow run publish.yml -R haltia-de/packages`).

`build-rootfs.sh` installs the meta packages from that repository, with each package file named in `linux-port/apps/packages.lock` (name repo version file sha256; refreshed by `linux-port/apps/update-lock.sh [NAME [vX.Y.Z]]`) fetched and checked against the lock's sha256 (the checksum holds are then dropped from the image's world, so the tablet can upgrade); whatever the lock does not name, or everything with `B8K_FROM_SOURCE=1`, it builds from the tag in `linux-port/apps/sources`. Keep the two files' versions in step. Packages renamed in ADR 0004 provide and replace their `b8k-` names, and the old command names stay as links until 3.0.

This repository keeps what is the device's: the session loop in `/etc/local.d/desktop.start` (`haltia-session ... phoc-gpu -C /usr/share/haltia/phoc.ini -E haltia-launcher`, `XDG_CURRENT_DESKTOP=Haltia:GNOME`), `b8k-suspend` (the shell's suspend hook `/usr/lib/haltia/hooks/suspend`), `b8k-usb`, `b8k-netwatch`, `b8k-sdslot`, `b8k-wdt-exrst`, `b8k-rdma-fifo.py`, zram, earlyoom, the speaker profile, zapret, iio-sensor-proxy and feedbackd in the image, the boot picture (`linux-port/initramfs/splash.py`: Haltia's sign on the device, Golos wordmark), and the doas rule for the USB switch (`z-b8k-device.conf`; the shell writes `z-haltia-shell.conf`). No xdg-desktop-portal on the B8000-H. The brand (sign, palette, icon style) is in haltia-de/.github, `brand/`.

## Architecture constraints that span files

- **No Android blobs in the repo or in images.** At boot, `linux-port/rootfs/b8k-android-system.initd` mounts the tablet's own stock `system` partition read-only. The PowerVR, gralloc and Wi-Fi firmware blobs are loaded from there. Never add proprietary binaries to the tree or to `make-release-rootfs.sh` output.
- **Storage safety.** The installer (`initramfs/init`, `install-root-to-emmc.sh`, `tools/*-acm.ps1`) writes only USRDATA (`mmcblk1p20` under the install DTB), and only after checking the DTB, the SD root device and the exact size of 27589888 sectors. Never write BOOT, RECOVERY, NVRAM, PRO_INFO, PROTECT_F/S or the partition table. Partitions in the development DTS are marked `read-only`. Keep these guards when you edit installer code.
- **Display path.** The display uses mediatek-drm over DSI and takes over the LK-initialized pipeline (patches 0017–0036: OVL/RDMA FIFO, BLS backlight, CRTC kept on across DPMS, cached dumb buffers). Runtime tuning such as the RDMA FIFO threshold lives in `linux-port/rootfs/b8k-rdma-fifo.py`. `docs/scroll-tear.md` explains why.
- **CPU frequency.** The CPU runs at up to 1209 MHz (vproc 1.2 V). An old 806 MHz cap (`00-b8k-stability.start`) was never part of the build and is gone. There is no thermal zone and no thermal throttling, so watch for heat under long load.
- **Reboot.** `mtk_wdt_restart` resets through TOPRGU (`0x10000000`), leaving `WDT_MODE` as LK set it (`0x79`). Without `EXRST_EN` (bit 2) the preloader keeps the tablet off. `rootfs/b8k-wdt-exrst` sets the bit at boot, and a successful reboot shows `boot_reason=4` in `/proc/cmdline`. Access `/dev/mem` there with 32-bit reads and writes only: a byte store raises a bus error.
- **Wi-Fi hangs.** `wlan_mt6628` sometimes stops passing traffic during large transfers (an scp of a few MB) while the link stays up. `rootfs/b8k-netwatch` pings the gateway and reloads the driver once; the panel shows `wifi-x.svg`. It also reloads once when the link has been gone for a minute with Wi-Fi switched on. Copy big files to the tablet over SSH in pieces of about 128 KB with pauses. Pushing base64 through the ACM shell lost data.
- **Sleep.** Only s2idle exists (there is no SPM code for MT6589, so no `deep`). The screen and touch survive it. The power key's PMIC IRQ wakes the tablet (`wakeup-source` in `mt6320.dtsi`). `wlan_mt6628` does not survive it, so `b8k-suspend` unloads `wlan_mt6628` and `wmt` before the sleep and reloads them after. bq24190 logs harmless "Transfer while suspended" warnings.
- **Power use.** The empty microSD slot (MSDC1, `11240000.mmc`) has no card detect and was polled every second (20 IRQ/s, an error line each time); `b8k-sdslot` unbinds it 20 s after boot when no card is in. `wlan_mt6628` takes `debug=3` (errors and warnings): its default logged every packet. phoc runs without `-v`, which logged every frame into `phosh.log`. Polling loops read sysfs with the `read` builtin rather than `cat`, and the panel polls Wi-Fi, the drawer handle and the battery every 30 s. Patch 0040 masks the OVL frame interrupt LK leaves enabled (the CRTC takes vblank from RDMA).
- **Timers.** The system counter is GPT6 (64-bit, free-running), but the CPUs see CNTPCT's high word through a latch that only moves when GPT6's registers are read; unread, CNTPCT jumps back 2^32 ticks (330 s at 13 MHz) at every wrap of the low word. That, not a 32-bit counter, is why patches 0008/0012 once turned the arch timer off. Since k23w (patches 0041, 0042) the arch timer gives each CPU its own tick (`NO_HZ_IDLE`, `HIGH_RES_TIMERS`), while time and sched_clock stay on the GPT. `set_next_event` reads GPT6 before each event and never programs one past `H:ffffffff`: an event across the wrap otherwise never fires (k23t hung at 660 s). Never let anything take time from CNTPCT on this SoC, and never use CNTVCT (CNTVOFF is garbage per CPU). Details in `docs/power.md`.
- **Memory.** Kernel 23 has zram. `b8k-zram` makes 512 MB of lz4 swap at boot, with `swappiness` 100. `earlyoom` (`rootfs/earlyoom.conf`) kills one user process when available memory is under 10% and free swap under 20%, browser processes first; it avoids phoc, whose process name is `ld-linux-armhf.` because it runs through the Debian loader. Firefox with one page takes about 550 MB, so `b8k-launcher` no longer starts it. uBlock Origin recompiled its filter lists now and then at 270-340 MB and froze the session once; `b8k-policies.py` in the b8k-firefox repository writes `/etc/firefox/policies/policies.json` (a copy of mobile-config-firefox's, which Firefox reads instead) with uBlock Origin Lite in complete mode. `b8k-lean.js` turns off Firefox's background features. Measurements: `docs/power.md`.
- **Wi-Fi MAC.** Without Android NVRAM, `wlan_mt6628` builds its MAC from the timer, and the MAC cannot be changed after the module loads. The module takes a `mac=` parameter, which the boot script derives from `/etc/machine-id`.
- GPU module sets are keyed by kernel build number: `/usr/lib/b8k/kN` (the old development tablet used `/root/kN`). `b8k-gpu` and `g3-run.sh` pick the set that matches the running kernel, and `make-release-rootfs.sh` keeps every set it finds.

## Windows tooling

`tools/*.ps1` and the SP Flash Tool XML configs are for Windows. They handle readback and flashing over the MediaTek preloader and stream images through the recovery USB ACM shell (`acm-shell.ps1`, `stream-emmc-acm.ps1`). Multiple versions of SP Flash Tool are kept under `external/spft-*`.

## Line endings

`.gitattributes` forces LF for `*.sh`, `*.patch`, `*.py`, `initramfs/init`, `Makefile` and `Kbuild`. Keep LF when you create files of these types, because the repo is also edited from Windows.
